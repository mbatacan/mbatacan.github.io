KAI is a multi-agent system that takes a Kaggle competition from a Slack command to a scored leaderboard submission. A run downloads the data, profiles it, engineers features, trains and blends models, decides whether the result is worth submitting, and reads back the score. Each agent posts a report to the Slack thread, and replies in that thread steer the next run.

Architecture

An orchestrator runs seven agents in sequence, passing files between them. It saves the run state to disk after every stage so a run can resume after a restart or a usage limit, and gives each stage a timeout. Every run is tracked in MLflow. The Critic decides whether to submit; KAI only submits when auto-submit is on.

Modeling

The Modeler trains a pool of LightGBM, XGBoost, CatBoost, RandomForest and a linear model on five shared folds, with a randomized search over 25 settings per family. It then hill-climbs blend weights on the competition's own metric. The blend is kept only if it beats the best single model by more than fold-to-fold noise, so most competitions end up with a single CatBoost model and only home-data keeps a blend. The metric shapes the pipeline: RMSLE trains on a log target, and accuracy gets a tuned decision threshold.

Feature engineering

A fixed toolkit does the generic work: splits composite columns, ordinal-encodes quality scales, adds log copies of skewed columns and drops id-like columns. The Engineer then adds domain features as named expressions. They must beat the toolkit baseline on a quick LightGBM check, and a run's feature set is promoted only if its cross-validation score beats the best on record, so later runs build on earlier ones. Nothing in the pipeline names a competition's columns.

Offline experiments that moved cross-validation by less than ±0.001: ExtraTrees, kNN, SVM and MLP ensemble members, a 13-model pool, seed averaging, PCA, count encodings, group aggregates and imputation variants.
