# mbatacan.github.io

Personal portfolio and blog, built with [Astro](https://astro.build) and hosted on GitHub Pages. The lab has two small ML demos.

**Live at:** https://mbatacan.github.io

## The lab

### Race an RL Paddler (`/lab/rl-paddler`)

An RL agent that steers an outrigger canoe (OC6) through cross-wind and cross-current. Race it, or watch it against a hand-coded baseline.

![Race an RL Paddler](docs/images/rl-paddler.jpg)

- A dropdown switches between trained PPO checkpoints; the panel under the game shows each one's settings, results against the baseline, and training curves.
- Physics, training and evaluation live in [ama-flow](https://github.com/mbatacan/ama-flow). This repo has a TypeScript port of its physics and a small re-implementation of each policy's network (an 18 -> 64 -> 64 -> 8 MLP).
- The port is tested against ama-flow's own output: `parity.json` holds golden trajectories and observation -> action pairs, and the tests require the TypeScript to reproduce them. Physics changes belong in ama-flow, not here.
- Models come from a Databricks model registry and are committed as JSON under `src/data/ama-flow/`, generated by ama-flow's exporter (don't edit by hand).

![Model info panel](docs/images/model-panel.jpg)

### Fool the Classifier (`/lab/fool-the-classifier`)

Draw something and see if a pretrained sketch classifier can guess it.

## Development

```bash
npm install
npm run dev        # dev server at http://localhost:4321
npm run build      # static build -> dist/
npm run preview    # preview the built dist/ locally
npm test           # vitest: physics/policy parity, game logic, stroke geometry
npx astro check    # type check (also run in CI)
```

CI (`.github/workflows/ci.yml`) runs the tests, the type check and the build on every pull request. Project structure, conventions and the workflows below are described in more detail in [CLAUDE.md](CLAUDE.md).

### Adding a blog post

Create `src/content/blog/<slug>.md`:

```markdown
---
title: "Post Title"
date: 2024-01-15
description: "One-sentence description shown in meta tags and the blog listing."
---

Post content in Markdown...
```

The blog index picks it up automatically, sorted by date. The URL becomes `/blog/<slug>`.

### Adding or updating a lab project

Edit `src/data/lab-projects.ts`. Each entry has a `status` of `completed`, `in-progress`, or `idea`, and the `/lab` page groups by that automatically. A `completed` entry needs an `href`; the other two render as a non-clickable card.

### Updating the RL models

Edit the model manifest in the ama-flow repo and re-run its exporter into `src/data/ama-flow/`; see "Adding/updating a model on /lab/rl-paddler" in [CLAUDE.md](CLAUDE.md).

## Deployment

Pushing to `main` triggers `.github/workflows/deploy.yml`, which builds the site and pushes `dist/` to the `gh-pages` branch. GitHub Pages must be set to serve that branch (Settings -> Pages -> `gh-pages` / root).
